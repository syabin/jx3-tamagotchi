## jx3-tamagotchi v7.1（commit 21d28b5，已推送）

### 日常页拿不到数据的根因（实测证据，别再重复排查）

- **jx3api 从不返回 `Access-Control-Allow-Origin`**：响应头只有 `Server: nginx` / `Content-Type` / `HSTS`，OPTIONS 预检也无 CORS 头 → 浏览器直连必被同源策略拦，这一条从项目第一天起就是如此。旧接口 `/data/daily`、`/data/server` 现已 404 下线。
- **不支持 JSONP**：`?callback=cb123`、`?jsonp=` 都被忽略，返回仍是纯 JSON。
- **之前能用的唯一原因是 r.jina.ai 中转**，它自带开放 CORS。现在该域名从国内网络彻底不可达（清空代理变量后 TCP 都建不起来，15s 超时，连首页都打不开；WebFetch 也 fetch failed）。
- **备用代理整站失效**：allorigins 与 codetabs 让它们代理 `example.com` 也返回 Cloudflare `522 error code`，即代理自身挂了/被拦，与目标站无关。corsproxy.io 要 API key（401）、cors.lol 429、whateverorigin 要 Origin 头。
- 境外可达性 OK：WebFetch（服务端）直接拿到 jx3api 200，说明接口无地域限制，GitHub Actions 美国节点应能抓取。

### 解决方案：构建时预取（零代理、零服务器）

- 新增 `.github/workflows/fetch-daily.yml`：cron `10 * * * *` + workflow_dispatch，curl 抓接口 → node 校验 `status===200 && detail.date` → 写 `data/daily.json`（`{fetchedAt,date,detail}`）→ 内容变化才 commit。
- `index.html`：`DAILY_SRC = "data/daily.json"`，全站只剩一处 `fetch`；本地缓存超 1 小时（`DAILY_REFRESH_MS`）自动重取；断网沿用旧缓存 `dailyStaleCache`。删除 `worker.js`、`DAILY_PROXY`、`DAILY_FALLBACKS`、`parseDaily`。
- 线上验证：`https://syabin.github.io/jx3-tamagotchi/data/daily.json` 返回 200 / `application/json`。
